# llm-harmony Slice 5 — `RESOLVE`

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `llm-harmony resolve <model>` — name a *model*, get back the coordinates of a provider ready to serve it. The verb Delroy actually needs.

**Architecture:** Placement keys on the **artifact path** a provider reports, not on its name. Three of the four publish one; slice 2's disk ledger already indexes paths by `(dev, ino)`, so a path match is proof rather than inference. Admission reuses slice 3's estimator. Activation starts a provider via slice 4 when needed. No eviction.

**Tech Stack:** Same crate. No new dependencies.

**Spec:** [`../architecture.md`](../architecture.md) §4, [`../design.md`](../design.md) §4.

---

## Why placement keys on paths

Measured 2026-09-10 against all four providers running simultaneously.

**By provider-local id there is no overlap at all** — 15 model entries, 15
distinct ids, nothing served by two providers. The ids simply differ for the
same model.

**By canonical name, slice 2's normaliser bridges one group and misses two:**

| Case | Result |
|---|---|
| `Qwen3.5-9B-ultra-uncensored-heretic-Q4_K_M` ↔ `...-MLX-4bit` | ✅ merged |
| `...Defiant-Heretic-`**`NEO-IMATRIX-MAX-MTP`**`-Q4_K_M` ↔ `...Defiant-Heretic-MLX-4bit` | ❌ missed |
| `...opus-`**`high-reasoning`**`-distill` (LM Studio) ↔ `...opus-distill` (llama.cpp) | ❌ missed |

One hit, two misses, on a corpus of nine groups. Name-based placement would
route by coin flip.

**Paths are reported, not inferred:**

| Provider | Path source | Recorded? |
|---|---|---|
| llama.cpp | `status.args` → `--model <path>` | yes |
| vLLM-MLX | `source` field on `/v1/status` | yes |
| Ollama | `digest` → `blobs/sha256-*` | yes, via slice 2's scanner |
| LM Studio | **nothing** — only `publisher`, `arch`, `quantization` | **no** |

So three providers give a fact, and LM Studio needs one bridging inference.
That is a far better position than nine groups of guesswork, and it respects
slice 2's rule that inferred edges may not silently drive decisions: the
LM Studio bridge is marked, and a resolve that depends on it says so.

## Global Constraints

- **No eviction.** Every slice so far added exactly one authority, and this one
  already adds placement and activation. When there is no room, `RESOLVE`
  returns `DENY`. Harmony still cannot destroy a resident model.
- **Never carry a request.** The output is a `base_url` and a provider-local
  model id. If this slice ever grows a proxy, the project has become llama-swap.
- **Inference must be visible.** A placement that relied on the LM Studio name
  bridge reports `inferred`, per slice 2's provenance rule.
- **No room is `DENY`, not a smaller model.** Substituting a different
  quantisation silently is the thing `field-notes.md` warns about — MLX
  conversion dropped MTP tensors and a vision tower. Alternatives may be
  *offered*; they may not be chosen.
- macOS only, as slices 1–4.

## Deliberately not in this slice

- **Eviction.** The next authority, and its own slice.
- **Substituting a different artifact.** Alternatives are offered, never chosen.
- **A daemon or socket.** `resolve` is a CLI call; Delroy shells out as it
  already does for `status`.
- **LM Studio path identity.** It publishes none. A bridge via its store layout
  (`{publisher}/{repo}/`) is possible and is inference; this slice marks it
  rather than pretending.
